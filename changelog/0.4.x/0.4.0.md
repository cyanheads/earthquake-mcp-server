# 0.4.0 — 2026-10-18

## Added

- **Feed continuation resource:** read `earthquake://feed/{magnitude_tier}/{time_window}/page/{cursor}` using the returned `next_uri`; feed resources now include `totalCount`, `truncated`, and continuation fields.

## Changed

- Rename `earthquake_search` to `earthquake_search_events` and `earthquake_count` to `earthquake_count_events`. Update callers; the old names have no aliases. (#38)
- **Result pages** fit 24,000 serialized UTF-8 bytes across both tool surfaces and feed resources. Feed/search limits still accept 1,000/20,000 respectively; search fetches at most 100 candidates and advances by the exact returned `nextOffset`. (#34)
- **Feed cursors** retain the first-read generation for up to 15 minutes, subject to capacity eviction and restart. Restart legacy cursors; expired generations return `cursor_expired`. Feed resource cache hints are private with zero lifetime. (#33)
- **Oversized results** fail explicitly with `result_too_large` when one event or page metadata cannot fit; generations exceeding 32 MiB of retained payload and charged metadata fail with `snapshot_too_large`.
- **Feed/search deadlines** cover retries and search's optional count within 50 seconds. Optional count timeout preserves events with `countUnavailable`; caller cancellation propagates.
- **Development guidance** follows the adopted framework API references and gated release procedure.
- **Dependencies and toolchain:**
  - `@cyanheads/mcp-ts-core` ^0.13.14 → ^0.13.15
  - `zod` ^4.6.5 → ^4.6.7
  - `@types/node` ^26.6.4 → ^26.6.5
  - `vitest` ^5.0.3 → ^5.0.4
  - Bun 1.4.2 → 1.4.3

## Fixed

- **Date bounds** resolve date-only values to midnight on both providers and anchor offsetless default windows in UTC. Explicit timezones/fractions and existing date padding are preserved; `queryEcho` carries the effective bounds. (#43)
- **Feed resource failures** carry typed recovery guidance and numeric status without captured upstream bodies; non-retryable failures remain non-retryable. (#45)
