# 0.3.0 — 2026-07-26

## Added

- **`source_catalog` / `auth` provenance fields** on `EarthquakeEventSchema` — the upstream catalog (e.g. `"EMSC-RTS"`) and the agency or network the source names as authoritative (EMSC `auth`, USGS `net`). Rendered on a new `**Provenance:**` line in `content[]` alongside status. Absent when the source reports none ([#22](https://github.com/cyanheads/earthquake-mcp-server/issues/22)).
- **`ignoredFilters` enrichment** on `earthquake_search` and `earthquake_count` — names the USGS-only filters (`alert_level`, `min_felt`, `min_significance`) dropped when `source=emsc`, so an unconstrained result is never mistaken for a filtered one ([#16](https://github.com/cyanheads/earthquake-mcp-server/issues/16)).
- **`upstream_rejected` error contract** on `earthquake_search` and `earthquake_count` — a declared reason distinct from `source_unavailable`, carrying the FDSN service's own 4xx rejection reason (offending parameter, accepted format) via a shared extractor in the new `src/mcp-server/tools/fdsn-error.ts` ([#26](https://github.com/cyanheads/earthquake-mcp-server/issues/26)).
- **`source_timeout` / `feed_timeout` error contracts** on `earthquake_search`, `earthquake_count`, and `earthquake_get_feed` — the `mcp-ts-core` 0.10.17 bump classifies a request timeout as `Timeout` (-32004) rather than `ServiceUnavailable`, which would otherwise bypass these tools' existing remaps; each now catches `Timeout` and throws its own declared reason with a recovery hint.

## Changed

- **Breaking: `status` and `tsunami` are nullable.** Both are `null` for every EMSC event — EMSC publishes no review status (previously hardcoded to `"reviewed"`) and no tsunami flag (previously hardcoded to `0`). A client branching on either field as always a string/number must handle `null` ([#22](https://github.com/cyanheads/earthquake-mcp-server/issues/22)).
- **`tsunami`'s description corrected** — the USGS flag marks a large event in an oceanic region; it is not a warning. Schema description and rendered text now point to tsunami.gov for actual alert status ([#22](https://github.com/cyanheads/earthquake-mcp-server/issues/22)).
- **`felt`, `cdi`, `mmi`, `alert`, `significance` descriptions** now distinguish "USGS computed none for this event" from "EMSC publishes no such field," replacing the flat "USGS only" framing ([#22](https://github.com/cyanheads/earthquake-mcp-server/issues/22)).
- **EMSC described as an independent global catalog, not European-regional** — across both tools' descriptions, the `source` enum on `earthquake_search`/`earthquake_count`, `createApp()`'s server instructions, and the README. EMSC's coverage is global; station density is highest around Europe and the Mediterranean ([#23](https://github.com/cyanheads/earthquake-mcp-server/issues/23)).
- **`formatEvent`'s `content[]` rendering** — status/catalog/agency grouped onto one `**Provenance:**` line; every impact field (DYFI felt reports, ShakeMap MMI, CDI, significance) that is absent is now named under `Not reported:` instead of silently dropped, so `content[]` conveys everything `structuredContent` carries ([#17](https://github.com/cyanheads/earthquake-mcp-server/issues/17)).
- **`scripts/clean-mcpb.ts` / `scripts/lint-packaging.ts`** — the MCPB bundle strip step and packaging lint now also remove and detect platform-specific `@duckdb/node-bindings-*` native binaries, which previously locked a bundle to the build host's platform and could push it past the 25 MB registry cap.
- **Dependencies:** `@cyanheads/mcp-ts-core` ^0.10.16 → ^0.10.17, `@biomejs/biome` ^2.5.4 → ^2.5.5, `ignore` ^7.0.5 → ^7.0.6, `tsc-alias` ^1.8.17 → ^1.9.1, `vitest` ^4.1.9 → ^4.1.10.

## Fixed

- **`earthquake_get_event`'s `not_found` error** now spreads `ctx.recoveryFor('not_found')` onto the thrown error, so the declared recovery hint reaches `data.recovery.hint` and `content[]` instead of being dropped ([#15](https://github.com/cyanheads/earthquake-mcp-server/issues/15)).
