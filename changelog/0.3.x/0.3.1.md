# 0.3.1 — 2026-07-26

## Added

- **`event_type` field** on `EarthquakeEventSchema` — carries USGS's `properties.type` (`"earthquake"`, `"quarry blast"`, `"explosion"`, `"ice quake"`) or EMSC's `evtype` code (`"ke"` known earthquake, `"ue"` unknown event); `formatEvent` renders it whenever it isn't `"earthquake"` ([#24](https://github.com/cyanheads/earthquake-mcp-server/issues/24)).
- **`event_type` filter** on `earthquake_search` and `earthquake_count` — forwarded as the USGS FDSN `eventtype` parameter. EMSC's endpoint rejects an `eventtype` parameter outright with HTTP 400, so it joins `alert_level`/`min_felt`/`min_significance` in `USGS_ONLY_FILTERS` and surfaces in `ignoredFilters` for `source=emsc` ([#24](https://github.com/cyanheads/earthquake-mcp-server/issues/24)).
- **`detail` object** on `earthquake_get_event` and the `earthquake://event/{event_id}` resource — a curated projection of the USGS single-event `products` blob: `losspager` (alert level, report URL), `shakemap` (max MMI/PGA/PGV, intensity map), `dyfi` (response count, max CDI, map URL), `moment_tensor` (scalar moment, derived depth, nodal planes), `ground_failure` (landslide/liquefaction alerts), `origin` (azimuthal gap, station count, location/depth uncertainty, review status), and `finite_fault` (rupture length/width, model URL). Each group is omitted, not nulled, when USGS produced no such product for the event ([#25](https://github.com/cyanheads/earthquake-mcp-server/issues/25)).

## Fixed

- **Unparseable upstream 4xx bodies no longer rethrow raw.** `earthquake_search` and `earthquake_count` now declare an `upstream_rejected_no_reason` contract for a boilerplate-only or HTML 4xx body — previously that path fell through to `throw err`, leaving `content[]` with a bare status code and the raw upstream body (including an EMSC-internal hostname) on `structuredContent.error.data` ([#27](https://github.com/cyanheads/earthquake-mcp-server/issues/27)).
- **`upstreamRejection` gates on `err.code`, not just the 400–499 status range** — only `InvalidParams`, `InvalidRequest`, and `ValidationError` are eligible for relabeling, so a 404 from a misconfigured base URL (classified `NotFound`) is never folded into `upstream_rejected` ([#27](https://github.com/cyanheads/earthquake-mcp-server/issues/27)).
- **`earthquake_get_event` and its resource declare `source_unavailable`/`source_timeout` contracts** — previously only `not_found` was declared, so a USGS outage or timeout reached the caller as an undeclared framework error with no recovery hint, unlike the matching contracts already on `earthquake_search`/`earthquake_count`/`earthquake_get_feed` ([#28](https://github.com/cyanheads/earthquake-mcp-server/issues/28)).
