# 0.3.2 — 2026-08-18

## Added

- **Bounding-box filters** — `min_latitude`, `max_latitude`, `min_longitude`, `max_longitude` on both `earthquake_search` and `earthquake_count`, each independently optional, forwarded verbatim (no unit conversion) to USGS and EMSC. Combinable with the existing `latitude`/`longitude`/`radius_km` circle — both groups intersect on both providers. Longitude accepts up to ±360 so a box can cross the antimeridian; only a strictly inverted `min > max` pair is rejected (`invalid_bounding_box`), an equal-value pair is a valid degenerate box ([#37](https://github.com/cyanheads/earthquake-mcp-server/issues/37)).

## Changed

- The 13 filter fields shared by `earthquake_search`/`earthquake_count` are now defined once, in `query-params.ts`'s `earthquakeFilterFields`, instead of duplicated per tool — closes the drift that let the two tools' `radius_km` bounds disagree ([#32](https://github.com/cyanheads/earthquake-mcp-server/issues/32)).
- `alert_level` on `source=usgs` now forwards `minalertlevel` instead of `alertlevel`, matching the input's documented "minimum PAGER severity." USGS's `alertlevel` is an exact match — a `green` minimum query was silently excluding yellow/orange/red events ([#31](https://github.com/cyanheads/earthquake-mcp-server/issues/31)).
- `min_depth_km`/`max_depth_km` are now bounded to `[-100, 1000]` km, USGS's documented catalog envelope. Unlike `radius_km`, this is a query-correctness bound, not an upstream-rejection avoidance — an out-of-range depth returned a genuine empty result before, not an error ([#32](https://github.com/cyanheads/earthquake-mcp-server/issues/32)).
- `radius_km`'s max tightened from `20002` to `20001.6` km, USGS's actual enforced ceiling — the old bound let `(20001.6, 20002]` pass local validation only to always fail upstream ([#32](https://github.com/cyanheads/earthquake-mcp-server/issues/32)).
- `@cyanheads/mcp-ts-core` `^0.10.17` → `^0.11.5` (MCP SDK `^1.29.0` → `^1.30.0` transitively), `typescript` `^6.0.3` → `^7.0.2`, `@biomejs/biome` `^2.5.5` → `^2.5.8`, `@types/node` `^26.1.1` → `^26.2.0`.
- Adopted the framework's tsconfig build/test split — tests are now typechecked (`tsconfig.json` includes `tests/**/*`; `tsconfig.build.json` carries its own `rootDir`/`include`/`noEmit: false`).
- Dockerfile production installs now pass `--omit=peer`, dropping optional peer tiers (test runner, service SDKs, parsers) Bun would otherwise auto-install.
- Added `.github/CONTRIBUTING.md` and `.github/CODE_OF_CONDUCT.md`; synced 12 skills to the current framework versions.
- Security contact updated to `security@caseyjhand.com` in `.github/SECURITY.md`.

## Fixed

- **`start_time`/`end_time` now validated and normalized before either upstream is queried** — a bare year expands to `-01-01`, an unpadded month or day is zero-padded, and malformed or ambiguous input (`03/05/2020`, an empty string, `last tuesday`) is rejected locally instead of round-tripping to USGS/EMSC or silently matching a zero or whole-catalog result. **Narrowing:** slash-separated dates like `03/05/2020`, which both upstreams accept today, are now rejected — day-first vs. month-first is ambiguous and neither provider documents which it applies ([#29](https://github.com/cyanheads/earthquake-mcp-server/issues/29)).
- `event_type` rejects empty/whitespace-only input locally instead of silently dropping it upstream while still echoing it as applied in `queryEcho`; `UsgsService.buildFdsnQuery()`'s `eventType`/`startTime`/`endTime` guards changed from truthy to `!= null`, matching every sibling field ([#32](https://github.com/cyanheads/earthquake-mcp-server/issues/32)).
- The bounded-response reader's elision marker (`…[N bytes elided]…`) joins a captured error body with no newline, so `fdsn-error.ts`'s line-splitting trailer guard could pass the trailing boilerplate — including EMSC's internal `ws2` hostname — through as agent-visible error text. Now truncates to only whole lines preceding the marker.
