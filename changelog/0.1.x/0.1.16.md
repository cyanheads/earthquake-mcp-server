# 0.1.16 — 2026-07-02

## Added

- **`queryEcho` enrichment on `earthquake_search`** — echoes the effective parameters sent upstream (including the server-resolved `start_time` default; USGS-only filters omitted for `source=emsc`), rendered in `content[]` via an `enrichmentTrailer` line ([#11](https://github.com/cyanheads/earthquake-mcp-server/issues/11)).
- **`buildQueryParams()`** (`src/mcp-server/tools/query-params.ts`) — shared tool-input → FDSN query-param builder for `earthquake_search` and `earthquake_count`, replacing the per-tool conditional-spread blocks.

## Fixed

- **EMSC full-catalog default** — omitting `start_time` now sends an explicit `starttime` of `end_time − 30 days` (or `now − 30 days`) to both sources; EMSC applies no upstream default and previously queried its entire ~27-year catalog ([#12](https://github.com/cyanheads/earthquake-mcp-server/issues/12)).
- **`totalCount` never populated** — the old condition compared returned-event count against the limit and never fired; both services now run a follow-up FDSN count query when results truncate at the limit, and the truncation `notice` carries the real match total. A count failure degrades to an absent `totalCount` ([#11](https://github.com/cyanheads/earthquake-mcp-server/issues/11)).
- **Null magnitude fabricated as `0`** — `magnitude` is now nullable end-to-end (`EarthquakeEventSchema`, feed resource, normalizers pass `p.mag ?? null` through), and `formatEvent()` renders "unknown"; mirrors the `depth_km` treatment ([#13](https://github.com/cyanheads/earthquake-mcp-server/issues/13)).
- **`feed_unavailable` contract never fired** — `earthquake_get_feed` now catches `ServiceUnavailable` from `getFeed()` and re-throws via `ctx.fail('feed_unavailable', …)` so `data.reason` and the recovery hint reach clients ([#14](https://github.com/cyanheads/earthquake-mcp-server/issues/14)).
