# 0.1.12 — 2026-06-04

## Fixed

- **`earthquake-feed` resource** — invalid `magnitude_tier` / `time_window` URI params now throw `validationError()` (-32007) instead of `notFound()` (-32001); error code now correctly reflects a bad-input failure rather than a missing resource ([#9](https://github.com/cyanheads/earthquake-mcp-server/issues/9)).
- **`earthquake_search` tool** — `source_unavailable` error contract now fires via `ctx.fail()` when the service layer throws `ServiceUnavailable`; `data.reason` is populated so agents can route on it ([#10](https://github.com/cyanheads/earthquake-mcp-server/issues/10)).
- **`earthquake_search` tool** — `query_too_broad` error contract now fires via `ctx.fail()` when `UsgsService.searchEvents` throws a plain `Error` with attached `.data.reason`; previously the attached code and reason were silently discarded and the client received `InternalError` (-32603) ([#8](https://github.com/cyanheads/earthquake-mcp-server/issues/8)).
- **`earthquake_count` tool** — `source_unavailable` error contract now fires via `ctx.fail()` when the service layer throws `ServiceUnavailable`; `data.reason` is populated ([#10](https://github.com/cyanheads/earthquake-mcp-server/issues/10)).
- **Tests** — assertions in `earthquake-feed-edge-cases` and `earthquake-feed` resource tests updated to match the new `ValidationError` code; new edge-case tests added for `source_unavailable` and `query_too_broad` contract paths in search and count tools.
