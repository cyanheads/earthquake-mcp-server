# 0.5.0 — 2026-10-28

## Added

- **Published `earthquake-guide` skill** — `skills/earthquake-guide/SKILL.md` is served over MCP as `skill://earthquake-guide/SKILL.md` through `createApp({ skills: 'skills' })`, so `resources/list` gains the skill and the `skill://{+path}` template. It ships in the npm package (`files`), the Docker image, and the MCPB bundle.
- **`earthquake_get_event` `include`** takes `origins`, `magnitudes`, `arrivals`, and `aftershock_forecast` (USGS only). Requested groups return `origins`, `magnitudes`, `arrivals`, and `aftershock_forecast`; a group USGS did not publish or that failed to load is listed in `unavailable_includes` as `not_published` or `fetch_failed`. Omitting `include` adds no group and no request. ([#41](https://github.com/cyanheads/earthquake-mcp-server/issues/41), [#54](https://github.com/cyanheads/earthquake-mcp-server/issues/54))
- **`depth_type`** on `earthquake_get_event`'s `detail.origin`, and on each `origins` entry, carries the published depth type (e.g. `operator assigned`), separating an assigned depth from a located one. ([#41](https://github.com/cyanheads/earthquake-mcp-server/issues/41))
- **EMSC event IDs** (`YYYYMMDD_NNNNNNN`) resolve in `earthquake_get_event` and `earthquake://event/{event_id}` through SeismicPortal, returning the event a search with `source: emsc` returns; EMSC events list every requested `include` group as `not_published`. USGS events in feed, search, and lookup results add `associated_ids`, the other IDs USGS answers for the event. ([#53](https://github.com/cyanheads/earthquake-mcp-server/issues/53))
- **`EARTHQUAKE_CLAMP_LIMITS`** (default `true`) clamps a search or feed `limit` above 1,000 to 1,000 with a `notice` naming the requested and applied values; `false` advertises and enforces `maximum: 1000` instead. Each clamp logs and increments the `earthquake.limit.clamps` counter. ([#58](https://github.com/cyanheads/earthquake-mcp-server/issues/58))
- **`fast-xml-parser`** ^5.11.2 as a runtime dependency, parsing the QuakeML phase-data product for `magnitudes` and `arrivals`.

## Changed

- **`earthquake_search_events` and `earthquake_get_feed`** return exactly `limit` events per page, fewer only on the last, with `nextOffset` and `nextCursor` advancing by that count; the byte-bounded page cut is gone. Default `limit` is 15 (was 100) and the cap is 1,000 (search was 20,000). Feed resources return 100 events per page. ([#58](https://github.com/cyanheads/earthquake-mcp-server/issues/58))
- **`DEFAULT_LIMIT`** accepts 1–1,000 (default 15). A value above 1,000 that 0.4.1 accepted now stops startup with an error naming the variable.
- **Event lookups** share the 50-second call deadline across the event request and every product request, retries included.
- **Packaging** — `server.json` and `manifest.json` declare `USGS_BASE_URL`, `EMSC_BASE_URL`, `DEFAULT_LIMIT`, and `REQUEST_TIMEOUT_MS` beside `EARTHQUAKE_CLAMP_LIMITS`, and the MCPB bundle offers each as an optional setting. Agent Plugins `plugin.json` and `mcp.json` added.

## Removed

- **`result_too_large`** error reason on search, feed, and feed-resource contracts, with the byte-budget wording in descriptions and notices. ([#58](https://github.com/cyanheads/earthquake-mcp-server/issues/58))
