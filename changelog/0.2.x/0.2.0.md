# 0.2.0 — 2026-07-26

## Added

- **`offset` input on `earthquake_search`** — 1-based, forwarded as the FDSN `offset` parameter on both USGS and EMSC. A capped result now carries `nextOffset` in `enrichment` alongside `truncated`/`totalCount`, and the truncation notice names the next call to make ([#19](https://github.com/cyanheads/earthquake-mcp-server/issues/19)).
- **`limit`/`cursor` inputs on `earthquake_get_feed`** — pages the precomputed feed via `paginateArray`. `totalCount`, `truncated`, and `nextCursor` are declared in `enrichment` and reach both `structuredContent` and `content[]`. The cursor is opaque and unrelated to `earthquake_search`'s numeric `offset` — USGS regenerates these feeds about once a minute, so a raw offset across two calls would skip or duplicate events ([#18](https://github.com/cyanheads/earthquake-mcp-server/issues/18)).
- **`queryEcho` enrichment on `earthquake_count`** — echoes the effective upstream parameters, including the server-resolved 30-day `start_time` default, so a bare count discloses the window it covers ([#21](https://github.com/cyanheads/earthquake-mcp-server/issues/21)).

## Changed

- **Breaking: `earthquake_get_feed`'s `count` and `events` now scope to the returned page, not the whole feed.** Previously a single call returned the entire precomputed feed (`month`/`all` could exceed 10,000 events); it now defaults to 100 events per call. Callers relying on `count` as the total feed size, or on `events` carrying every event in one response, must page with `cursor`/`nextCursor` to reach the rest. The `earthquake://feed/{magnitude_tier}/{time_window}` resource is unchanged and still returns the whole feed in one read.

## Removed

- **`query_too_broad` error contract** removed from `earthquake_search`, along with the HTTP-400 body parser it depended on and the `if (!response.ok)` branches across both services (`getFeed`, `searchEvents`, `countEvents` on USGS; the EMSC pair) — `fetchWithTimeout` already throws a status-mapped error on any non-2xx before returning a `Response`, so all of it was unreachable ([#20](https://github.com/cyanheads/earthquake-mcp-server/issues/20)).

## Fixed

- **EMSC zero-match searches** — EMSC answers any zero-match query, including an offset past the last match, with `204 No Content` and an empty body; `JSON.parse('')` threw, so a genuinely empty result surfaced as an opaque error. `EmscService.searchEvents` now treats an empty body as a match set of size zero.
- **Search/count/feed result types resolving to `any`** — `Awaited<ReturnType<typeof getUsgsService.prototype.searchEvents>>` accessed `.prototype` on a factory function rather than a class, which silently typed as `any`. Now typed via `UsgsService['searchEvents']` / `['countEvents']` / `['getFeed']`.
